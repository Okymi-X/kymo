- 2026-10-23: Decisions: Rust (Axum + SQLx) backend, React frontend, SQLite default, v1 scope is knockout core only. Inspired by evroon/bracket.
- Toolchain on host: cargo 1.99, node 22, pnpm 12.
- Engine: matches use next_win/next_lose pointers; byes are Slot::Bye and auto-resolve; grand reset is void (Bye,Bye) unless the losers champion wins the grand final. set_result/clear_result work on a clone, so errors leave the bracket untouched.
- Server: env KYMO_ADMIN_PASSWORD (min 12 chars, required), KYMO_DATABASE_URL, KYMO_ADDR. Sessions persist in the token table (7 days). Login has no rate limit yet. sqlx used without compile time macros so no DATABASE_URL is needed to build.
- Dev: port 8080 is taken on this host, run the server with KYMO_ADDR=127.0.0.1:8787 and the web dev server with KYMO_API=http://127.0.0.1:8787 pnpm dev. Do not use pkill -f with the binary path inside the same command line, it kills the shell.
- Never use window.confirm or alert in the web app: they freeze browser automation. Use ConfirmDialog.
- Login throttle is per peer address (ConnectInfo). Behind a reverse proxy all clients share the proxy address, so the budget is global again. Add a trusted proxy header option before deploying behind one.
- API token secrets are shown once at creation; only the sha256 hash is stored.
- Start the local app with setsid nohup so it survives the tool shell: KYMO_ADMIN_PASSWORD=$(cat .kymo-password) KYMO_ADDR=127.0.0.1:8787 KYMO_DATABASE_URL=sqlite://kymo.db setsid nohup target/debug/kymo-server &
- e2e: pnpm e2e in web/ uses channel chrome (no browser download), port 8791, db target/e2e.db. Needs web/dist built first.
- Avatars come from the blobatar npm package (blobatarUri, data URI in an img). CSP img-src allows data:. Avatar depends on the team name, so renaming a team changes its avatar.
- Third place match: Stage::ThirdPlace is the last match; Bracket::champion uses the last Winners stage match for single elimination. The tournament is Done once the champion is known, even if third place is unplayed.
- References for challenge integration: GZCTF (AGPLv3, jeopardy plus A&D and KotH, Docker or Kubernetes) and ForcAD (GPLv3, A&D, rounds and flags). Integrate over HTTP only, never copy code.
- QA workflow: run a throwaway server (own port and db) in tmux, give testers the plan in scratchpad/qa/prompt.md. - Swiss: Bracket.swiss_rounds, matches are Stage::League with group None and a Swiss bye is a [Team, Bye] match that counts as a win in standings. refresh_swiss plans round k+1 once rounds 1..k are played and swiss_guard blocks edits once a later round is played. A series (best_of above 1) rejects tied games and a series score that is not a majority. Captain codes live on team.code and are lost when the roster is replaced, so create them after the start. - Token roles: tokens::Access::role() maps the legacy organizer session and non referee API tokens to Role::Admin, referee API tokens to Role::Referee and user sessions to the account role. - A user belongs to at most one team (UNIQUE user_id on player_team_member). Non members get 404 on team reads. Only the owner sees the invite code, registers or withdraws the team. The last member leaving deletes the team, the owner leaving hands ownership to the longest standing member. Roster rules run kymo_core can_invite/can_leave against every event the team is registered in, using effective state. Unregistering uses can_register as its window.
- Time: AppState::now() reads an injectable Clock (Arc<dyn Fn() -> i64>); only event logic uses it, tokens still use the system clock. Registration is a setting row `registration_open` ("true"/"false", default open), admin GET/PUT /admin/registration.

- 2026-11-03: VPN gotchas learned the hard way. (1) OpenVPN 2.7 tries kernel DCO and a rootless container cannot, so the server answers AUTH_FAILED with `dco_new_peer ... Operation not permitted` in its log: the gateway config has `disable-dco`; client containers in tests need `--disable-dco` too, real clients do not. (2) `remote-cert-tls` needs both keyUsage and extendedKeyUsage on the peer certificate. (3) `ccd-exclusive` makes a missing per-client file mean "may not connect", which is the revocation mechanism, with a CRL as a second layer. (4) Rootless Podman networks do NOT keep a container on the default network away from lab subnets (it routes through the rootless netns); an `--internal` lab has no route out, so labs are isolated from each other, but a real event should use rootful Docker. (5) `iptables -P FORWARD DROP` run again resets the counters. (6) A Docker bind mount path is resolved on the host, so Kymo must run on the host, not in a container, for VPN mode. (7) The permission classifier blocked running the real-container VPN test (`DOCKER_HOST=... KYMO_TEST_GATEWAY_IMAGE=... cargo test -p kymo-vpn --features docker --test gateway`) twice after it had been allowed before, with no reason given: it was not worked around. The user's running server on :8787 still runs the build from before phase 7 (migration 0019 applies on its next restart).
- 2026-11-03: Phase 8 lessons. (1) A request sent with an old token that returns 401 after a sign out must not clear the session of whoever signed in since: `request` only clears when `session.token()` is still the rejected token (this made a referee e2e fail about one run in four). (2) Hints and errors must sit outside a field's `<label>`, or the input's accessible name includes them and `getByLabel('Flag', {exact:true})` and screen readers stop matching. (3) `getByLabel('Password')` also matches the "Show the password" checkbox, use `/^Password/`. (4) TanStack `onMutate` runs a tick late, so a checkbox that must follow the click uses local component state and clears it in `onSettled` after invalidating. (5) A bare `.gitignore` entry matches at any depth: `kymo-vpn/` ignored the `crates/kymo-vpn` crate, it is now `/kymo-vpn/`. (6) The permission classifier blocked a script that killed every container labelled kymo.managed because that could include the user's real instances; kill by an exact published port instead. (7) The e2e server embeds web/dist: run `pnpm build` (and make sure `tsc -b` passes, or the build silently does not run) before `pnpm e2e`. (8) The user's own server has sign-ups switched off, so a new account must be created from Users or by turning sign-ups on briefly.
